# Клиент SynchrotronSim — архитектура и поэтапный план

Живой интерактивный кокпит бесконечного режима (режим 4): встроенный 3D-вид установки,
real-time графики величин модели, подписка на любой сигнал, сохранение раскладки окон.
Документ — ориентир для сессии, которая будет это строить.

## 0. Что уже есть (переиспользуем, не строим заново)

- `gui/` — оболочка PySide6 над CLI (выбор проекта, вкладки, журнал). Кокпит открывается из неё
  (кнопка «Режим 4») и работает отдельным окном; плюс запускается standalone.
- `control/mode5_realtime.py` — пошаговый real-time цикл (`TbtPlant`+`Scheduler`, чтение «ручек» на
  лету). Его тело переезжает в поток движка; вместо записи HTML — публикация снимка.
- `control/state.py` — доска `ExperimentState`/`StateView` с регионами `config/actual/dynamics/
  target_slots/observables/refs/sensors/noise/beam/machine/optics/undulators/drives/history`.
  Это **единственный источник данных** для клиента (читаем), и ручки (пишем командой).
- `visualize.py` / `viz_html.py` — построение глиф-геометрии кольца/ондулятора. `scene3d`
  переиспользует их код, чтобы живая сцена совпадала с батч-визуализацией.

Новые зависимости — только две: `pyvistaqt` (встроить PyVista в Qt), `pyqtgraph` (потоковые графики).
Установка: `py -3.14 -m pip install pyvistaqt pyqtgraph`.

## 1. Хребет: поток-движок → снимок доски → подписчики по адресу

Движок и UI живут в разных потоках. Движок крутит модель с полной скоростью и владеет доской;
UI в главном потоке Qt (~30 кадров/с) читает снимок и рисует. Между ними — шов `Link`.

**Та же граница — это и клиент-серверная граница.** Сейчас транспорт внутрипроцессный
(`InProcLink`, двойной буфер + очередь). Позже — сетевой (`NetLink`, сокет) без ломки UI: UI и
движок не знают, какой транспорт под ними. Поэтому через шов ходят **только сериализуемые данные**
(числа + строковые адреса), никаких живых объектов доски. 3D-рендер всегда локальный — по проводу
идут числа, не пиксели.

```
client/link.py        Link (ABC): subscribe/unsubscribe/command/control/snapshot; Snapshot (dataclass);
                      InProcLink (потоки). NetLink — этап 7.
client/engine.py      EngineThread: тело mode5 (TbtPlant+Scheduler), очередь команд, модельное время
                      Σdt vs стенные часы → оценка скорости; публикует снимок подписанных адресов + мета.
client/addresses.py   КОНТРАКТ: канонический адрес сигнала. Перечисление адресов из StateView,
                      address→value, address→метаданные (имя, единицы, тип виджета). Адреса СТАБИЛЬНЫ
                      между запусками (id элемента, имя контура), иначе не восстановится раскладка.
```

### Схема адресов (черновик, уточняется на этапе 0)

- `element.<dev>.<attr>` — положение, углы, вибрации (закон+параметры), поле. Из `config`/`actual`/`drives`.
- `drive.<aid>.{field,slew,lag_tau,odz,res,act}` — из `DriveView`.
- `obs.<name>` — `obs.ebpm.x`, `obs.tune`, `obs.chroma`, `obs.adts`. Из `observables`.
- `optics.<attr>@<dev>` — `optics.beta_x@q1`, `optics.eta_x@...`. Из `OpticsView`.
- `undulator.<id>.{gap,K,E1,orbit_kick}` — из региона `undulators`.
- `screen.<id>` — структурный (heatmap Вт/мм² + спектр на оси). Пересчёт на медленном такте.
- `sensor.<id>` — точка (x,y).
- `loop.<name>.{gain,error,enabled}` — состояние контура (для дерева проекта).

### Link — интерфейс (эскиз)

```
client→engine:  subscribe(addr) / unsubscribe(addr) / command(addr, value)
                control("run"|"stop"|"restart") / set_screen(addr, area, res)
engine→client:  poll_snapshot() -> Snapshot{ values:{addr:val}, meta:{model_time, wall_time,
                                              speed, cycle} }   # только подписанное + мета
```

## 2. UI (главный поток, QMdiArea)

- **Центр — 3D-сцена** (`scene3d.py`, `pyvistaqt.QtInteractor`): кольцо глифами, ондулятор набором
  магнитов (расстояние = текущий зазор), стартовая плоскость, опорная орбита пунктиром, вход/выход
  элементов и дрейфов полупрозрачными квадратами, сенсоры (экранами), экраны + пунктир ондулятор→экран.
  Каждый актёр помечен адресом. Hover → имя; ПКМ → инфо-панель.
- **Окна-подписчики** (субокна MDI, перемещаемые) — один паттерн «виджет на адрес», наследники базы:
  - `graph` — pyqtgraph-линия real-time + вкладка настроек (цвет, история, масштаб авто/фикс, легенда);
  - `point` — движущаяся точка сенсора со следом;
  - `screen` — heatmap + спектр + настройки (площадь, разрешение = ручка скорость↔точность);
  - `info` — атрибуты элемента из StateView; клик по атрибуту открывает подписчика.
- **Дерево проекта** (dock) — второй вход к адресуемой модели (контуры/наблюдаемые/приводы не имеют
  «тела» в 3D): `установка · контуры · ондуляторы · экраны · сенсоры · приводы`, двойной клик открывает
  инфо/график.
- **Панель управления** (субокно) — пуск/стоп/рестарт + модельное время + оценка скорости.
- **Оконный менеджер** (тулбар) — закрыть всё, плиткой, каскадом, показать/скрыть доки, сохранить/
  загрузить именованную раскладку. Плитка/каскад/закрыть-всё — штатные методы `QMdiArea`.

## 3. Персистентность раскладки (вместо логина)

Раскладка = сериализованный список подписчиков. Каждое окно описывается полностью:
`{тип, адрес(а), настройки, геометрия}` + камера 3D + состояние доков → JSON.

- авто-`last`: сохраняем при выходе, поднимаем при входе («мои графики на своих местах»);
- именованные раскладки — отдельные файлы: `workspace/layouts/<проект>/<имя>.json` (gitignore).

Восстановление = пересоздать подписчиков и переподписать на **текущий** прогон по адресу — работает
только потому, что адреса стабильны (см. контракт в §1). Мульти-пользователь позже — ключуем ещё по имени.

## 4. Этапы (с критерием «готово»)

- **Этап 0 — зависимости и шов.** Поставить `pyvistaqt`, `pyqtgraph`. `link.py` (Link/Snapshot/InProcLink),
  `addresses.py` (схема + перечисление/резолв по StateView).
  Готово: юнит-тест перечисляет адреса из посеянного состояния и резолвит несколько в верные значения;
  InProcLink проходит круг subscribe→snapshot на фейковом цикле.
- **Этап 1 — движок в потоке.** `EngineThread` (тело mode5), очередь команд (run/stop/restart + одна
  ручка, напр. зазор), публикация снимка подписанных адресов + мета (model_time, speed, cycle).
  Готово: headless-тест гоняет поток N циклов; фейк-клиент подписан на `obs.ebpm.x` и зазор, командует
  смену зазора, видит отражение; оценка скорости > 0.
- **Этап 2 — скелет кокпита + 3D + панель времени.** `cockpit.py` (QMainWindow+QMdiArea), `scene3d.py`
  (встроенный PyVista, вся геометрия из §2), панель управления. Кнопка «Режим 4» в оболочке + standalone
  `py -3.14 -m client --exp N`.
  Готово: запуск, кольцо живое, «пуск» — модельное время и скорость идут; сцена отражает командованную
  смену зазора.
- **Этап 3 — пикинг и инфо-панель.** Пометка актёров адресом; hover→имя; ПКМ→инфо-панель из StateView;
  атрибут в панели кликабелен и открывает подписчика.
  Готово: наведение показывает имя; ПКМ по квадруполю открывает панель с его положением/углами/полем;
  клик по «полю» открывает график.
- **Этап 4 — подписчики (все типы).** База `SubscriberWindow` + `graph`/`point`/`screen`/`info`. Экран —
  пересчёт на медленном такте, завязан на `control/recorders.py ScreenRecorder` (паттерн+E₁ уже есть).
  Подзадачи независимы, можно вести параллельно.
  Готово: каждый тип открывается из дерева или из 3D/инфо, обновляется вживую; разрешение/площадь экрана
  меняют скорость↔точность.
- **Этап 5 — дерево проекта + оконный менеджер.** Dock-дерево → двойной клик открывает инфо/график;
  тулбар: закрыть всё, плиткой, каскадом, тумблеры доков.
  Готово: дерево обходит модель, контуры видны, действия тулбара работают.
- **Этап 6 — персистентность раскладки.** `layout.py`: сериализация окон+камеры+доков в JSON; авто-`last`
  при выходе, именованные save/load; `workspace/layouts/<проект>/`.
  Готово: открыть несколько окон, закрыть, открыть снова → окна на местах, переподписаны на живые данные;
  именованные раскладки сохраняются/грузятся.
- **Этап 7 (на потом) — NetLink.** Вторая реализация `Link` по сокету (напр. ZeroMQ: PUB/SUB на снимки +
  отдельный канал команд), снимки только-подписанное/дельты, движок headless как сервер, клиент по локалке.
  Явно отложено.

## 5. Сквозные ограничения

- **Ядро заморожено.** Клиент только читает `StateView` и шлёт ручки штатным путём (команда → `Limits` →
  plant). Диффур-ядро, карты поля, токи — не трогаем.
- Коммит/пуш — только по явной просьбе. `workspace/layouts/**` — в gitignore.
- Запуск: `py -3.14`, `SS_SECTOR=1`, `PYTHONPATH=C:/Sasha/Work/SILA/SynchrotronSim`.
- Новый пакет `client/` (рядом с `gui/` и `control/`), запускается standalone и открывается из оболочки.
