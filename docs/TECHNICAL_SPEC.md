# Техническое задание — SynchrotronSim

Симулятор динамики пучка синхротрона **СИЛА (SILA)**. Считает траектории заряженных
частиц по решётке магнитов двумя независимыми ядрами и предоставляет инструменты для
их взаимной калибровки и настройки решётки.

---

## 1. Назначение

- Моделировать пролёт пучка по кольцу СИЛА и подбирать токи магнитов так, чтобы пучок
  устойчиво циркулировал по проектной орбите.
- Иметь два взаимопроверяющих ядра: **эталонное** (по реальному 3D-полю из ANSYS) и
  **быстрое** (матричное), и уметь переносить настройку между ними через матрицы связи
  «ток → физический коэффициент».
- Все управляющие параметры магнитов — **токи обмоток** (для электромагнитов) и
  **поправочные коэффициенты** (для постоянных магнитов).

## 2. Архитектура

Два ядра трекинга над общей базой данных решётки и общей библиотекой полевых карт.

| | Диффурное ядро | Матричное (киковое) ядро |
|---|---|---|
| Что | Интегрирование уравнений движения (метод Бориса) по 3D-картам поля ANSYS | drift–kick–drift по физическим коэффициентам элементов |
| Роль | **Эталон физики** | Быстрая модель / оптимизация |
| Реализация | C++ `build/SynchrotronTracker.exe` (`src/main.cpp`, `Integrator.h`, `FieldMap.h`, `LatticeManager.h`) | `matrix_tracker.py` + `src/MatrixTracker.h` |
| Вход | токи (`arg_val`) + коэф. диполей (`correct_coeff`) | физкоэф. `mat_*` ИЛИ токи → матрица связи → `mat_*` |

Опорная жёсткость пучка `QP = q/p₀ = −84.925 м⁻¹·Тл⁻¹`. Электроны, β≈0.99, γ≈6.98.

## 3. Функциональные категории

1. **Чтение LTE и заполнение БД.** Парсинг Elegant `.lte` → таблицы решётки (шаблон
   супериода `sp_elements`, полная развёртка `lattice_layout`, сборка `lattice_configs`),
   warm-start физкоэффициентов из проектных `K` (`lte_to_lattice.py`,
   `assemble_lattice_configs.py`, `lte_warmstart.py`, `warmstart_ring.py`,
   `lte_to_design_orbit.py`, `design_orbit.py`, `build_matrix_db.py`, `synthetic_library.py`).

2. **Карты полей.** Хранение и чтение 3D-карт ANSYS (`.fld`/`.bin`, per-1A или per-100A),
   генерация синтетических карт для элементов без ANSYS-расчёта
   (`field_quality.py`, `scan_field_maps.py`, `synthetic_assets.py`, `gen_synthetic_maps.py`).

3. **Сглаживание и симметризация карт.** Устранение артефактов расчётной сетки/решения:
   наложение медианной симметрии (Bx,By нечётны по z, Bz чётно) и денойз по чётностям
   (`clean_dipole_maps.py`, `symmetrize_map.py`).

4. **Матричное ядро.** Быстрый трекинг drift–kick–drift, универсальный мультипольный
   элемент (нормальные+скью мультиполи, вертикальный диполь, край), экспорт траекторий и
   показаний BPM (`matrix_tracker.py`, `matrix_traj_export.py`, `src/MatrixTracker.h`).

5. **Диффурное ядро.** Интегрирование по картам поля (C++ `SynchrotronTracker.exe`),
   инжекция пучка из произвольной плоскости, финиш-плоскость для замыкания оборота
   (`src/*`, `beam_injection.py`, `src/FinishPlane.h`).

6. **Сравнение моделей и матрицы связи.** Прогон одного элемента обоими ядрами, подгонка
   матрицы связи «токи → (изгиб, градиент, секступоль, …)», в т.ч. для многообмоточных
   (SP, DQ) по комбинациям токов; обратный перевод физкоэф.→токи
   (`build_coupling_pipeline.py`, `combo_coupling.py`, `phys_to_current.py`,
   `element_matrix_compare.py`, `match_coefficients.py`, `validate_coupling_table.py`,
   `single_element_boris.py`, `build_coupling_table.py`, `track3.py`).

7. **Глобальная настройка.** Оптимизация всех ручек сразу — на диффурном ядре
   (`build/SynchrotronOptimizer.exe`, драйвер `optimize.py`) и на матричном
   (`matrix_optimizer.py`); авто-режим-продолжатель (ползущий рубеж выживания по кольцу)
   `continuation_tuner.py` / `tune.py`.

8. **Оконная настройка.** Оптимизация по скользящему окну магнитов (тот же
   `SynchrotronOptimizer.exe`, режим `windowed`); генерация оконных конфигов
   `prepare_optim_config.py`, `make_nsp_drift_configs.py`, `make_nsp_next_configs.py`.

Дополнительно: визуализация (`visualize.py`, `live_visualizer.py`, `viz_shot.py`),
синхронизация токов шаблона супериода из настроенной решётки (`sync_sp_elements.py`),
служебные (`reset_magnets.py`, `manual_kick.py`, `apply_optim_history.py`).

## 4. Модель данных (`workspace/tables/`, `;`-CSV)

| Таблица | Роль |
|---|---|
| `sp_elements.csv` | Шаблон супериода: `(sp_type, sp_element_id, device_type_id, arg_val, correct_coeff)`. **Редактируется руками**; общие токи размножаются на всё кольцо. |
| `lattice_layout.csv` | Полная развёртка кольца: `global_id`, `(sp_type, sp_element_id)`, координаты/ориентация магнитов. |
| `lattice_configs.csv` | Собранная решётка: per-instance токи/коэф. + физкоэф. `mat_*` (изгиб/градиент/секступоль/…) для матричного ядра. |
| `hardware_library.csv` | Типы устройств: путь к карте, `eff_length`, `nominal_arg`, `field_direction`, `correct_coeff`, `edge_ff`, STL. |
| `coupling_matrix.csv` | Матрица связи per-устройство: `per_B/per_G/per_S/per_O` (+скью) — вклад тока в физкоэф. |
| `experiments.csv` | Эксперименты: решётка, группа пучка, `dt`, финиш-плоскость (3 точки + направление). |
| `particle_groups.csv` | Пучки: стартовые частицы (плоскость, смещения). |
| `bpm_config.csv` / `bpm_readings.csv` | Модель несовершенства датчиков положения / накопленные показания. |

Карты полей — `workspace/fields_bin/*.bin` (заголовок 96 б: сетка + `nominalArg`),
`workspace/fields_raw/*.fld` (текст ANSYS).

## 5. Режимы трекинга (`track3.py`)

1. **`--mode diff`** — диффурное ядро: аргументы = токи (`arg_val`) и коэф. диполей
   (`correct_coeff`). Эталон.
2. **`--mode kick-phys`** — матричное ядро на **проектных физкоэффициентах** (`mat_*`).
3. **`--mode kick-current`** — матричное ядро на **токах** → через `coupling_matrix` → `mat_*`.

Для согласованности режимов 1/3 токи получают из `mat_*` конвертером `phys_to_current.py`.
Полный оборот замыкается финиш-плоскостью в плоскости инжекции.

## 6. Типовой сценарий использования

1. Загрузить `.lte` → заполнить БД, warm-start физкоэф. из проектных `K`.
2. Прогнать трекинг **матричным ядром** (на физкоэф.), убедиться в замыкании кольца.
3. Рассчитать **матрицы связи** (сравнение элементов обоими ядрами) → перейти к токам.
4. Прогнать трекинг **диффурным ядром** (на токах), подтвердить расчёты.
5. **Выгрузить траектории** и **показания BPM** в БД.
6. При необходимости — глобальная / оконная настройка токов для устойчивой циркуляции.

Возможность запускать: диффурную модель (на токах), матричную на физкоэф., матричную на токах.

## 7. Состав репозитория

- **Ядро** — `*.py` в корне (65 модулей) + `src/*` (C++) + `build/*.exe` + `workspace/*` (данные) + `docs/*`.
- **Легаси** — `legacy/scripts/` (скрипты опытов, билдеры отчётов) и `legacy/external/`
  (внешние коды BIP, MAD, Elegant, BDSIM для сверки). В прод-сценарии не используются.

Границу «ядро/легаси» определяет граф импортов от точек входа: всё, что достижимо от
команд сценария, — ядро; остальное — легаси (вынесено, обратимо).
