# Техническое задание — SynchrotronSim

Симулятор динамики пучка синхротрона **СИЛА (SILA)**. Считает траектории заряженных частиц по
решётке магнитов двумя независимыми ядрами и предоставляет инструменты для их взаимной проверки
и настройки решётки.

---

## 1. Назначение

- Моделировать пролёт пучка по кольцу СИЛА и подбирать настройки магнитов так, чтобы пучок
  устойчиво циркулировал по проектной орбите.
- Иметь два взаимопроверяющих ядра: **эталонное** (интегрирование по реальному 3D-полю из ANSYS)
  и **быстрое** (киковое).
- Сверяться с внешним образцом: `elegant` на том же `.lte` (`elegant_run/`).

## 2. Архитектура

Два ядра трекинга над общей базой данных решётки и общей библиотекой полевых карт.

| | Диффурное ядро | Матричное (киковое) ядро |
|---|---|---|
| Что | Интегрирование уравнений движения (интегратор Бориса) по 3D-картам поля ANSYS | drift–kick–drift по физическим коэффициентам элементов |
| Роль | **Эталон физики** | Быстрая модель / оптимизация |
| Реализация | C++ `build/SynchrotronTracker.exe` (`src/main.cpp`, `Integrator.h`, `FieldMap.h`, `LatticeManager.h`) | `matrix_tracker.py` |
| Вход | токи (`arg_val`) + коэф. диполей (`correct_coeff`) | физкоэф. `mat_*` из `lattice_configs` |

Опорная жёсткость пучка `QP = q/p₀ = −84.925 м⁻¹·Тл⁻¹`. Электроны, β≈0.99, γ≈6.98.

**Оба ядра читают конфигурацию из `lattice_configs.csv`** — Python в `matrix_tracker.py:186`, C++ в
`src/main.cpp:174` (по индексам столбцов, поэтому новые столбцы добавляются только В КОНЕЦ схемы).

*Токовый режим матричного ядра архивирован:* связь «ток → физкоэф.» не была доверенной, поэтому
киковое ядро читает только `mat_*` (проектные `K` из `.lte`). Вместе с ним архивированы таблицы
`coupling_matrix` / `element_coupling`, калибровочные скрипты и C++ матричное ядро (`MatrixTracker.h`) —
единственный матричный движок сейчас `matrix_tracker.py`.

## 3. Функциональные категории

1. **Чтение LTE и заполнение БД.** Проверка и замыкание `.lte` (`lte_ring.py`), загрузка по пути
   (`load_config.py`), парсинг → таблицы решётки (шаблон супериода `sp_elements`, развёртка
   `lattice_layout`, сборка `lattice_configs`), warm-start физкоэф. из проектных `K`
   (`lte_to_lattice.py`, `assemble_lattice_configs.py`, `lte_warmstart.py`, `warmstart_ring.py`,
   `lte_to_design_orbit.py`, `design_orbit.py`, `build_matrix_db.py`, `synthetic_library.py`,
   `s2lattice_to_db.py`). Снимок генерируемых таблиц — `db_snapshot.py`.

2. **Карты полей.** Хранение и чтение 3D-карт ANSYS (`.fld`/`.bin`), генерация синтетических карт
   для элементов без ANSYS-расчёта (`field_quality.py`, `scan_field_maps.py`, `synthetic_assets.py`,
   `gen_synthetic_maps.py`). Базовые карты `workspace/fields_bin/` разложены по подпапкам типа
   (`quadrupole/`, `sextupole/`, `octupole/`, `dipole_quadrupole/`, `dipole/`, `synthetic/`);
   ссылка — `hardware_library.map_bin_path`. Базовые карты QP/SP/OP/DQ сняты при 100 А
   (`nominal_arg=100`); синтетика строится ресайзом ОЧИЩЕННОЙ карты эталона.

3. **Сглаживание и симметризация карт.** Устранение артефактов сетки/решения и асимметрии:
   - `clean_dipole_maps.py` — медианная симметрия средней плоскости (Bx,By нечётны по z, Bz чётно),
     убирает паразитное медианное поле диполей (DP).
   - `symmetrize_map.py` — проекция на симметрию МУЛЬТИПОЛЯ с учётом ЧИСЛА ПОЛЮСОВ: отражения по
     чётностям + грид-точный **поворот 90°**, разделяющий квадруполь (n=2) и октуполь (n=4);
     секступоль (n=3) — отражения. `symmetrize_maps.py` — драйвер.

4. **Матричное (киковое) ядро.** Быстрый трекинг drift–kick–drift, универсальный мультипольный
   элемент (нормальные+скью мультиполи, вертикальный диполь, край), экспорт траекторий и показаний
   BPM (`matrix_tracker.py`, `matrix_traj_export.py`, `beam_injection.py`).

5. **Диффурное ядро.** Интегрирование по картам поля (C++ `SynchrotronTracker.exe`), инжекция пучка
   из произвольной плоскости, финиш-плоскость для замыкания оборота (`src/*`, `src/FinishPlane.h`).

6. **Сверка моделей.** Прогон обоими ядрами одного эксперимента (`track3.py`), поэлементное
   сравнение с elegant (`elegant_run/`), стенд сравнения ядер на опытных конфигах
   (`element_bench.py`, `kickdoc_compare.py`, `elegant_model.py`). Поэлементное сравнение диффур↔кик —
   `element_compare.py` (свип токов, фит физкоэф+общий L_eff, Word-отчёт, комбо-датасеты DQ, 3D-наложение
   обеих моделей для `visualize.py`; изгибающие — в проекции Френе). См. `docs/MANUAL.md` §10.

7. **Глобальная настройка.** Оптимизация всех ручек сразу — на диффурном ядре
   (`build/SynchrotronOptimizer.exe`, драйвер `optimize.py`) и на матричном (`matrix_optimizer.py`);
   авто-продолжатель (ползущий рубеж выживания) `continuation_tuner.py` / `tune.py`.

8. **Оконная настройка.** Оптимизация по скользящему окну магнитов (`optimize.py --method=windowed`,
   `optimize_combined.py`); генерация конфигов `prepare_optim_config.py`.

Дополнительно: визуализация (`visualize.py`, `live_visualizer.py`, `viz_shot.py`, `viz_html.py`),
синхронизация токов шаблона из настроенной решётки (`sync_sp_elements.py`), служебные
(`reset_magnets.py`, `manual_kick.py`, `apply_optim_history.py`).

## 4. Модель данных (`workspace/tables/`, `;`-CSV)

| Таблица | Роль |
|---|---|
| `sp_elements.csv` | Шаблон супериода: `(sp_type, sp_element_id, device_type_id, arg_val, correct_coeff)`. **Редактируется руками**; значения слота размножаются на все супериоды. |
| `lattice_layout.csv` | Развёртка кольца: `global_id`, `(sp_type, sp_element_id)`, координаты/ориентация. |
| `lattice_configs.csv` | **Собранная решётка — её читают ОБА ядра.** Строка на экземпляр: геометрия, `arg_val`/`correct_coeff`, физкоэф. `mat_*`, структурные столбцы (`eff_length`, `kind`, `n_slices`, `edge1`, `edge2`). |
| `element_connectivity.csv` | Порядок обхода: предшественник/преемник каждого экземпляра. Источник правды. |
| `hardware_library.csv` | Типы устройств: путь к карте, `eff_length`, `nominal_arg`, `field_direction`, `correct_coeff`, `edge_ff`, `edge_delta`, STL. |
| `experiments.csv` | Эксперименты: решётка, пучок, `dt`, финиш-плоскость (3 точки + направление) и **параметры ядра** (`loss_radius_mm`, `plane_same_tol_mm`, `plane_parallel_tol`, `n_slices`). |
| `particle_groups.csv` | Пучки: стартовые частицы (в МИРОВЫХ координатах). |
| `bpm_config.csv` / `bpm_readings.csv` | Несовершенства датчиков положения / накопленные показания. |

`lattice_configs` / `lattice_layout` / `sp_elements` **генерируются и гитигнорятся**; их состояние
фиксирует снимок `workspace/tables/snapshot_design/` (`db_snapshot.py`).

Карты полей — `workspace/fields_bin/*.bin` (заголовок 96 б: сетка + `nominalArg`),
`workspace/fields_raw/*.fld` (текст ANSYS).

**Установки:** `1` — СИЛА, полное кольцо (2082 магнита, замкнутое); `2` — Сибирь (сторонний импорт,
144 магнита); `3` — SP1, первый супериод СИЛЫ (53 магнита). Они сосуществуют в одних таблицах:
загрузка одной установки не имеет права трогать строки другой.

## 5. Режимы трекинга (`track3.py`)

1. **`--mode diff`** — диффурное ядро: аргументы = токи (`arg_val`) и коэф. диполей
   (`correct_coeff`). Эталон физики.
2. **`--mode kick-phys`** — киковое ядро на **проектных физкоэффициентах** `mat_*`.

Установка и пучок берутся из `experiments.csv[exp]`. Полный оборот замыкается финиш-плоскостью в
плоскости инжекции; если финиш ≠ старт, путь считается открытым сегментом.

**Параметры ядра** (`matrix_tracker.Settings`): приоритет **аргумент > столбец `experiments.csv` >
дефолт**. Ни одного зашитого числа в расчётном коде.

## 6. Ключевые конвенции физики

- **Знак изгиба.** Положительный `ANGLE` из `.lte` = поворот **ВПРАВО** (yaw убывает), как в
  elegant/MAD ⇒ `+x` смотрит **наружу** кольца. Единственный источник — `lte_to_lattice.step`.
  Следствие: `k1=+K1`, `k2=+K2`, `k3=+K3` из `.lte` верны дословно,
  `mat_B = −ANGLE/(QP·L_eff)`. Зеркальная укладка требует переворота знака у киков, ЧЁТНЫХ по x
  (диполь ∝x⁰, секступоль ∝x²), и не требует у нечётных (квадруполь ∝x¹, октуполь ∝x³).
- **Мультиполи вдоль орбиты.** В изгибающих элементах кик берёт `u = x − x_ref`, где `x_ref` —
  прогиб опорной дуги от оси прямого ящика (сагитта `L·θ₀/8`). Иначе сама опорная ловит кик
  `k1·сагитта`. `elegant` решает это конструктивно: `CSBEND` — СЕКТОР, рама гнётся вместе с орбитой.
- **Замыкание кольца** проверяется по ДВУМ условиям: `Σ ANGLE = 2π` и зазор по положению при
  прогоне всей линии **с дрейфами**.
- **Тюн не применяется по умолчанию:** `mat_*` = проектные `K` из `.lte`, чтобы сверка с elegant
  шла на одних и тех же коэффициентах.

## 7. Типовой сценарий использования

1. Проверить `.lte` (`lte_ring.py`), при необходимости замкнуть кольцо.
2. Загрузить конфигурацию в БД по пути (`load_config.py`), получить `mat_*` = проектные `K`.
3. Прогнать трекинг **киковым ядром**, убедиться в замыкании кольца.
4. Прогнать трекинг **диффурным ядром**, сравнить с киковым.
5. Сверить с внешним образцом (`elegant`) поэлементно.
6. Траектории и показания BPM выгружаются в БД.
7. При необходимости — глобальная / оконная настройка для устойчивой циркуляции.
8. Зафиксировать состояние БД снимком (`db_snapshot.py save`).

## 8. Состав репозитория

- **Ядро** — `*.py` в корне (58 модулей) + `src/*` (C++) + `build/*.exe` + `workspace/*` (данные) +
  `docs/*` + `elegant_run/*` (оснастка сверки с elegant).
- **Легаси** — `legacy/scripts/` (скрипты опытов, билдеры отчётов), `legacy/external/` (внешние коды
  BIP, MAD, Elegant, BDSIM), `legacy/matrix_cpp/` (C++ матричное ядро). В прод-сценарии не нужны.

Границу «ядро/легаси» определяет граф импортов от точек входа: всё, что достижимо от команд
сценария, — ядро; остальное — легаси (вынесено, обратимо).
